# Cocoa reproduction runs

These directories are generated by `scripts/fit_cocoa.jl` from the original
observations and published priors. They are diagnostic artifacts, not new
literature parameter files. Read each `report.toml` before using its estimates;
`converged=false` or an absent report means the fit is not accepted.

The run settings record source hashes, seed, solver tolerances, sampler or
optimizer choices, and Julia version. Newer runs also record implementation
hashes and tentative per-start MLE parameters. Existing runs are preserved.
The latest runner also saves each completed MLE start and each retained Bayesian
draw immediately. Checkpoint files alone do not constitute an accepted fit and
cannot resume the sampler's adaptation state.

The same interrupted batch launched box Bayesian jobs: box 1 failed while
loading a package DLL with an explicit paging-file error, and box 2 produced no
fit directory. They supplied no retained draws. Subsequent validation and fitting
use one Julia process at a time.

`status.toml` documents runs stopped before a final report. Their logs remain in
the ignored local `.julia-depot/` directory. An interrupted chain is not a
posterior sample. Production runs require new output directories; the source
defaults and commands are documented in `docs/cocoa_fitting.md`.

The fit report's `reproduction_accepted` flag checks convergence and the P2.4
parameter-interval criterion. `curve_comparison.toml` separately checks the
preselected 2% figure tolerance for posterior means and medians. Neither changes
the published parameter files or the raw digitization to improve agreement.

New MLE runs preserve native optimizer success separately and additionally require
the independently recomputed projected log-parameter gradient to meet the recorded
tolerance. Earlier fit reports retain their original semantics and flags; a
historical native `Success` is not evidence that this additional check passed.
Diagnostic directories do not contain accepted fits or posterior uncertainty.
